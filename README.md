# Корпоративный календарь

Прототип работы с задачами события и перепиской между пользователями.

## Состав проекта

- `db.py` — SQLite-соединение и схема БД.
- `auth.py` — пользовательская сессия и проверки ролей/доступа.
- `event_service.py` — доступ к событиям, состав команды и участники события.
- `task_service.py` — бизнес-логика задач и комментариев.
- `ui/main_window.py` — окно списка задач.
- `ui/create_task_dialog.py` — создание задачи.
- `ui/comments_dialog.py` — история и отправка комментариев.
- `ui/assign_dialog.py` — назначение исполнителя тимлидом.
- `ui/task_card.py` — карточка задачи.
- `main.py` — точка входа и демонстрационные данные.
- `chat/service.py` — личные сообщения, чаты событий, поиск пользователей.
- `chat/window.py` — окно переписки.
- `run_chat_demo.py` — отдельный запуск для проверки чата.

## Запуск

Python 3.10+:

```bash
python -m pip install -r requirements.txt
python main.py
```

По умолчанию база `tasks_app.db` создаётся рядом с `main.py`. При первом запуске создаются демонстрационные пользователи, команда и событие. Демонстрационный вход — пользователь `lead` (тимлид). Для проверки роли участника измените `DEMO_USER_ID` в `main.py` на `2`.

## Форматы даты и времени

Вводите дедлайн и напоминание в формате `YYYY-MM-DD HH:MM`, например `2026-11-02 18:30`.
Поле напоминания необязательно. Пустое поле сохраняется как SQL `NULL`.

## Важные решения

- Логика задач находится в `task_service.py`, логика переписки — в `chat/service.py`.
  Общая проверка доступа к событиям находится в `event_service.py`.
- Участник автоматически становится исполнителем своей задачи; переданное UI значение исполнителя не даёт участнику назначить другого пользователя.
- Назначать исполнителя может только тимлид команды, связанной с событием.
- Комментарии доступны только пользователям, имеющим доступ к событию.
- Для доступа используются `events.creator_id`, `events.visibility`, `event_members` и `team_members`.
- `change_task_status` разрешает менять статус исполнителю, создателю задачи или тимлиду соответствующей команды.
- SQLite хранит даты как строки ISO-подобного формата `YYYY-MM-DD HH:MM`. В реальном приложении при переходе на PostgreSQL слой подключения можно заменить.

## Переписка

В окне задач появилась кнопка «Чат события». Она открывает переписку выбранного события.
Слева находятся доступные групповые чаты и существующие личные диалоги, справа — история
и поле ввода. Новые сообщения проверяются раз в две секунды. Enter отправляет сообщение,
Shift+Enter добавляет строку.

Кнопка «Новый диалог» открывает список пользователей с поиском по имени, фамилии или
логину. Сразу видны до 20 человек; остальные находятся через поиск. Поиск работает
без учёта регистра, в том числе на русском. Он также доступен над основным списком
под подписью «Поиск людей». После выбора человека можно отправить первое сообщение.
В основном списке личный диалог появляется после первой отправки.

Групповые переписки подписаны как «Событие». В открытом чате события кнопка «Участники»
показывает автора, тип доступа и людей, которые видят переписку. Состав берётся из
общих правил доступа к событию. Создание событий и изменение доступа относятся к
модулю событий; в демонстрации события и их участники заданы заранее.

Групповой чат возвращает последние 50 сообщений. В личной переписке загружается вся
история между двумя участниками. Список чатов отсортирован по последнему сообщению;
доступные события без сообщений находятся внизу. Сообщения хранятся в UTC,
в окне время переводится в местное время компьютера.

### Проверка на одном компьютере

```bash
python -m pip install -r requirements.txt
python run_chat_demo.py
```

В стартовом окне выберите Павла и нажмите «Открыть чат». Затем выберите Анну и откройте
второе окно. В окне Павла нажмите «Новый диалог», выберите Анну, отправьте сообщение
и проверьте ответ из второго окна. Также можно открыть администратора: даже с пустым
списком переписок он может выбрать собеседника через «Новый диалог».
Два окна используют один файл `chat_demo.db` рядом со скриптом.
Файл `tasks_app.db` основного приложения при этом не меняется.

Можно запустить два отдельных процесса из одной папки проекта:

```bash
python run_chat_demo.py --user 1
python run_chat_demo.py --user 2
```

В демонстрационной базе есть общий чат команды, приватное событие Анны и закрытое
обсуждение Павла с Анной. Иван не видит закрытое обсуждение, а личный план Анны
доступен только ей. Выбор пользователя нужен для демонстрации и не заменяет вход
в готовое приложение.

На Linux должен быть установлен Tkinter. Например, в Debian/Ubuntu это пакет
`python3-tk`, в Arch Linux — `tk`. На Windows Tkinter обычно поставляется с Python.

### Границы модуля и подключение

`ChatService(database, current_user)` получает существующий объект `Database` и
пользователя `auth.User`. Методы:

- `send_group_message(event_id, sender_id, text)` — отправить сообщение в событие;
- `get_group_messages(event_id)` — получить последние 50 сообщений;
- `send_private_message(sender_id, receiver_id, text)` — отправить личное сообщение;
- `get_private_messages(user1_id, user2_id)` — получить историю двух пользователей;
- `get_user_chats(user_id)` — получить список переписок;
- `search_users(query)` — найти собеседника.
- `get_group_info(event_id)` — получить автора, тип доступа и участников чата события.

Пустая строка в `search_users` возвращает начальный список пользователей. В списке
и в результатах поиска не больше 20 человек; текущий пользователь не включается.

Сообщение содержит `id`, `sender_id`, `text`, `created_at`, `sender_name` и идентификатор
события или получателя. Элемент списка чатов содержит `type` (`group` или `private`),
`id`, `title`, `last_message`, `last_message_at`, `last_message_id`. Для групп `id` —
идентификатор события, для личных диалогов — идентификатор собеседника.

Личные сообщения разрешены между пользователями приложения. Чужую историю читать
нельзя, отправителя подменять нельзя. При неверном вводе сервис выдаёт `ValueError`,
при отсутствии доступа — `AuthorizationError`. SQL и проверки находятся в сервисах,
интерфейс вызывает их методы и показывает результат.

Окно создаётся как `ChatWindow(master, database, current_user, event_id=None)`.
Переданный `event_id` сразу открывает групповой чат. Используется общий цикл
обработки событий Tkinter. При закрытии окна его таймеры останавливаются.

### Общая схема и доступ

В `users` добавлены `first_name` и `last_name`, в `events` — `creator_id` и `visibility`.
Новые события должны указывать автора и один из трёх типов доступа:

- `private` — только автор, даже если другой пользователь администратор или тимлид;
- `restricted` — автор и пользователи из `event_members`;
- `public` — автор, участники команды события и её тимлид.

`event_members` выполняет роль таблицы `event_access` из персонального задания.
Вторая таблица с теми же данными не создаётся. Правила реализованы в
`EventService.has_access_to_event` и используются как чатом, так и задачами.
При отзыве доступа групповой чат исчезает из списка, чтение и отправка запрещаются.
Личные сообщения от изменения доступа к событию не удаляются.

`Database.init_db()` автоматически обновляет старую схему без удаления данных.
Старые события становятся ограниченными, их списки участников сохраняются.
Поскольку в прежней схеме автор не хранился, при первом обновлении автором старого
события назначается тимлид его команды. При объединении модулей это решение и новые
поля нужно учитывать в создании событий. Старые пользователи получают пустые имя
и фамилию; для них в интерфейсе отображается логин.

Приложение работает локально с SQLite. Для переписки между разными компьютерами
нужна общая серверная часть, которой в этой версии нет.

### Автоматическая проверка

```bash
python -m unittest discover -s tests -v
```

Проверяются личные диалоги, все типы доступа к событиям, отзыв доступа, поиск на русском,
порядок чатов, последние 50 сообщений, сохранение истории и обновление старой базы.
Также проверяются ограничение списка пользователей и состав участников по доступу.
Есть проверка совместимости с созданием задач и комментариев. Тесты используют
временные базы, рабочие файлы не изменяются.
